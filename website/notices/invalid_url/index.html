Diagnosis

What this notice means

Definitions for valid URLs are quite vague. We perform strict validation using the Apache Commons UrlValidator.

Operational effect

Why it matters

The value is not a usable URL, so the link is dead wherever a consumer shows it — an agency site, a route page or a stop's information page.

Scope

Affected files and report fields

The affected file is determined at validation time. Use the filename or related context field in your report to locate it.

Report fieldTypeMeaning
This notice has no structured context fields.

Diagnosis

What usually causes it

  • The scheme omitted: www.example.com rather than https://www.example.com.
  • A spreadsheet wrapping the value in a hyperlink formula, so the cell exports as =HYPERLINK("…").
  • Spaces or line breaks inside the value.
  • A placeholder such as N/A or none left in an optional column that would have been fine left empty.

Repair

How to fix it

Write a complete absolute URL including the scheme: `https://example.com/routes/10`. Relative paths, bare hostnames and text such as `see website` are not URLs.

  1. 1
    Locate the record

    Open agency.txt and use the report fields below to find the exact row.

  2. 2
    Change the source data

    Apply the repair described above to that record, and leave unrelated rows alone.

  3. 3
    Validate again

    Rebuild the GTFS archive and confirm that invalid_url no longer appears for the record.

Do not do this: If you have no URL for a row, leave the field empty rather than inventing one. An optional URL column accepts blanks; it does not accept a link that 404s.

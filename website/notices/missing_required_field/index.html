Diagnosis

What this notice means

The given field has no value in some input row, even though values are required.

Operational effect

Why it matters

A field the specification requires is empty in this row. The record cannot be interpreted without it, so consumers usually drop the row — and a dropped `stop_times.txt` row removes a stop from a trip without any other signal that something is wrong.

Scope

Affected files and report fields

The affected file is determined at validation time. Use the filename or related context field in your report to locate it.

Report fieldTypeMeaning
csvRowNumberintegerThe row of the faulty record.
fieldNamestringThe name of the missing field.
filenamestringThe name of the faulty file.

Diagnosis

What usually causes it

  • A source record that was never completed — a stop added to the scheduling system without coordinates, or a route without a name.
  • A spreadsheet export that wrote an empty string where the source system had a null.
  • Rows shifted by one because an earlier row contains an unquoted comma inside a value, so a required column lines up against blank text.
  • A CSV assembled by concatenating exports with different column orders.

Repair

How to fix it

Fill in the real value for the row named in the report. The column exists; only this row's cell is empty, so this is a data gap rather than a schema problem.

  1. 1
    Locate the record

    Open the file named in the report and use the report fields below to find the exact row.

  2. 2
    Change the source data

    Apply the repair described above to that record, and leave unrelated rows alone.

  3. 3
    Validate again

    Rebuild the GTFS archive and confirm that missing_required_field no longer appears for the record.

Do not do this: Do not fill the cell with a placeholder such as 0, N/A or unknown to clear the error. A stop_lat of 0 is a valid coordinate off the coast of Africa, and N/A in stop_name is what riders will see in the app.
